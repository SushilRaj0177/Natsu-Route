# NatsuRoute（なつルート）

暑い日に、なるべく日なたを歩かずにすむ電車・バスの経路を、家の前から目的地の前まで案内します。対象は東京23区です。高齢の方と、その方を気づかう家族のためにつくりました。公共交通オープンデータチャレンジ2026への応募作品です。

![13時04分の建物の影の地図と、乗り換えの案内](docs/desktop.png)

ふつうの乗換案内は速さで経路を選びます。けれど暑い午後には、同じ行き先でも、道のどちら側を歩くか、駅のどの出口を使うか、バス停に日陰があるかで、直射日光を浴びる時間が14分にも3分にもなります。NatsuRoute は、建物と樹木の3D都市モデルから「その時刻に、その場所が日陰かどうか」を計算し、それをふまえて経路を選びます。

## できること

- **まず「日なたの時間」。** どの候補も、直射日光を浴びる時間をいちばん上に出し、移動全体を1本の帯（日なた・日陰・屋根の下・待ち・乗車）で示します。涼しい道を選ぶと何が変わるかも書きます。*「いちばん早い道より3分長いですが、日なたが11分短くなります。」*
- **歩道のどちら側を歩くか。** 歩道は道路の中央ではなく両脇にあるので、左右の歩道を別々に計算し、*「左側の歩道で100 m（半分日陰）」* のように案内します。
- **家を出る時刻。** 日なたのバス停で長く待たずにすむように出発時刻を合わせます。待ち時間も数えます。ホーム（屋根の下）か、道ばたのバス停か、日なたか日陰か、屋根やベンチがあるか。
- **駅の出入口を番号で。** 段差なしで使えるかどうかも示します。階段を使えない設定のときは、階段しかないとわかっている出入口には案内しません。坂や段差は国土交通省の歩行空間ネットワークデータ（ほこナビ）から取っています。
- **途中で休める場所。** 東京都の指定する暑さをしのぐ施設（クーリングシェルター、開いている時間つき）、コンビニ、給水、トイレ、ベンチ。
- **暑さ指数**（WBGT、環境省）の今と時間ごとの予測、熱中症警戒アラート。**「時間をずらすと？」** では同じ経路を1日の7つの時刻で計算し、涼しい時間を選べます。
- **電車もバスも。** 鉄道15社（JR東日本、東京メトロ、都営、東急、小田急、京王、西武、東武、京急、相鉄、つくばエクスプレス、りんかい線、ゆりかもめ、横浜市営地下鉄、多摩モノレール）の時刻表と、都営・東急・西武・国際興業バス。ノンステップバスには印をつけます。運賃は **東京都シルバーパス**（70歳以上の都民向けの年間パス。都営の電車・バスと都内の路線バスで使えます）を持っている場合の金額でも出せます。
- **日陰の地図。** 建物・高架・樹木の影を、選んだ時刻で描きます。経路は日なたと日陰で色分けします。
- **使いやすさ。** ユニバーサルデザインフォント（BIZ UDPゴシック）、最初から大きめの文字（ひとまわり小さく・大きくもできます）、高コントラスト表示、56 px のボタン、スマホの音声での読み上げ、「家族に送る」ボタン（共有シートまたは LINE）、印刷、日本語と英語、ライトとダーク、ホーム画面に追加。
- **一年中使えます。** 冬は日なたの道を、雨の日は屋根のある道を選べます。環境省が暑さ指数を出さない11月〜4月は、**「夏の日で試す」** で去年の夏の実際の1日（その日の暑さ指数と太陽の動き）を、今の時刻表で再現できます。

## どれくらい変わるか

[`pipeline/tools/study.ts`](pipeline/tools/study.ts) で、23区内のランダムな（シード固定の）経路を、この夏いちばん暑かった2026年7月22日の暑さと日差しで計算しました。表は [docs/study.md](docs/study.md) にあります。

- **13時、家から目的地まで**（114経路、1.5〜7 km）：直射日光を浴びる時間の中央値は、いちばん早い経路で **11.1分**、いちばん涼しい経路で **5.8分**。涼しい候補があった85経路では、所要時間が中央値で **5.8分** 長くなりました。
- **400〜1,200 m の徒歩：** 暑さをふまえた道は、日なたの時間を中央値で20〜26%減らし、歩く時間は1分ほど増えるだけでした。
- **バス停：** 10時〜14時、23区のバス停6,565か所のうち **58〜68%** が直射日光の下にあります。屋根やベンチをどこに置けば効果が大きいかを考える区役所にとって、そのまま使える一覧です。

これはモデルの計算結果で、実際に浴びた日差しを測ったものではありません（「精度と限界」を参照）。

アプリでの例：巣鴨のとげぬき地蔵から東京都健康長寿医療センターまで、再現した7月22日の13時04分に出発。いちばん早い経路は日なた14分、いちばん涼しい経路は日陰のバス停から草63系統に乗って日なた3分で、到着は3分おそくなるだけです。

![日なた3分のいちばん涼しい経路と、日なた14分のいちばん早い経路](docs/desktop-results.png)

## しくみ

```
PLATEAU 3D都市モデル ──┐ 建物、樹木、高架、バス停の屋根
OpenStreetMap ─────────┼─► 影をつくるもの ──► 日陰エンジン：胸の高さから太陽へ
                       │                       向けて光線を飛ばす（どの時刻でも）
OpenStreetMap ─────────┤ 歩行ネットワーク
ほこナビ（国交省） ────┴─► 屋根、地下通路、階段、エレベーター、坂、段差

ODPT 時刻表 ─────────────► 電車 + バス ─────► RAPTOR
環境省 ──────────────────► 暑さ指数、アラート ─► 日陰への回り道にどれだけの価値があるか
東京都クーリングシェルター ► 休める場所
```

1. **日陰。** PLATEAU の建物・樹冠・高架・バス停の屋根など約300万件（PLATEAU に樹木がない地域は OpenStreetMap の木）を、高さの範囲つきの輪郭にします。「13時04分にこの場所は日なたか」は、胸の高さ（1.2 m）から太陽の方向へ光線を飛ばし、24 m 四方の格子を通して、光線が横切る輪郭を高さの範囲と照らし合わせて判定します。高架はその下を日陰にしますが、低い太陽が下から差し込む場所は日なたのままです。樹冠は光を少し通します。光線1本の計算は約8 µs です。
2. **歩道。** 車道のある道は、中央線から車道幅の半分だけ離れた左右の歩道で日陰を調べます（建物の中に入ってしまう場合は道路側に戻します）。これで、どちら側が日陰かがわかります。
3. **徒歩。** 114万本の道の区間でダイクストラ法を使い、日なたの秒数と余分に歩く秒数をはかりにかけます。重みはその時刻の暑さ指数（「ほぼ安全」なら日なた1秒につき0.3秒の回り道、「危険」なら4秒まで）と、本人の選んだ優先（涼しさ・バランス・速さ）で決まります。歩いているあいだも太陽は動きます。
4. **家から目的地まで。** 出発地からの徒歩と、目的地へさかのぼる徒歩で、歩ける範囲の駅の出入口とバス停をすべて求め、RAPTOR の出発点と到着点にします。日なたを多く通って着く停留所は「遅く着く」ものとして扱うので、探索は日陰の多い停留所を選びやすくなります。これを重みなし、暑さに応じた重み、より強い重みの3通りで行います。候補はそれぞれ実際の行程として組み直します。徒歩が決まったあとの最も早い便、歩く時刻での日陰、待ち時間、運賃、休める場所。到着時刻・日なた・乗り換え・徒歩のどれでも他に負けない候補を残し、ラベルをつけます。
5. **日陰の地図。** 地図タイルは同じデータからサーバーで描きます。影は、輪郭が高さの範囲の下端から上端まで太陽と反対へずれたときに通る範囲です。屋上は消してあるので、地図には人が歩く場所の日陰だけが出ます。

## 動かし方

Node 20 以上、Python 3.11 以上、ビルド用に空きディスク約6 GB とメモリ8 GB、[developer.odpt.org](https://developer.odpt.org/) の ODPT キー（通常のキーとチャレンジ2026のトークン）が必要です。

```sh
cp .env.example .env            # ODPT_API_KEY, ODPT_CHALLENGE_TOKEN, CONTACT_EMAIL を記入
npm ci
pip install -r geo/requirements.txt

# 地理データ（最初の1回、30〜60分）：23区の PLATEAU、関東の OSM、
# ほこナビ、クーリングシェルター
mkdir -p data/raw/osm && curl -L -o data/raw/osm/kanto.osm.pbf \
  https://download.geofabrik.de/asia/japan/kanto-latest.osm.pbf
npm run geo

# 時刻表（約6分）と、再現する夏の日
npm run data

npm run dev                     # API は :8787、アプリは http://localhost:5173
```

便利なツール：

- `npx tsx pipeline/tools/plan.ts 35.7369,139.7337 35.7508,139.7019 2026-10-14T13:00:00+09:00 2026-07-22` でターミナルから経路を検索
- `npx tsx pipeline/tools/study.ts` で上の検証をやり直す
- `npx tsx pipeline/tools/bench-shade.ts` で日陰エンジンの速度を測る
- `npm test`、`npm run typecheck`

## 公開する

[Dockerfile](Dockerfile) はイメージの中ですべてをビルドします。ODPT キーはビルドシークレットとして渡します。

```sh
docker build \
  --secret id=odpt_api_key,env=ODPT_API_KEY \
  --secret id=odpt_challenge_token,env=ODPT_CHALLENGE_TOKEN \
  -t natsuroute .
docker run -p 8787:8787 -e ODPT_API_KEY -e ODPT_CHALLENGE_TOKEN -e CONTACT_EMAIL=you@example.com natsuroute
```

サーバーは約1.2 GB のメモリを使い（日陰のデータと歩行ネットワークをメモリに置くため）、約6秒で起動します。経路検索は0.5〜1.5秒、日陰の地図タイルは1枚10〜40ミリ秒で、キャッシュされます。

## 精度と限界

- 日陰は建物と樹木のデータから計算した推定です。日よけ、看板、パラソル、雲は含みません。曇りの日は、表示より日差しが弱くなります。
- 樹木のデータは十分ではありません（PLATEAU の樹木は都心の一部だけ）。並木道は実際より日なたに見えることがあります。
- 日陰を計算するのは23区内だけです。23区の外の徒歩は「日陰不明」と表示し、経路を選ぶときは日なたとして扱います。
- 駅の中（出入口からホームまで）の時間は推定です。駅の出入口は OpenStreetMap のもので、885駅に出入口があり（全部で2,831か所）、347か所が段差なし、628か所が階段のみ、残りは不明です。
- JR東日本と小田急は運賃をオープンデータで公開していないため、推測はせず「運賃は含まれていません」と表示します。東急・小田急・西武・京急の列車は駅の時刻表から組み立てているため、まれに少しずれる便があります。京成、東京モノレールなどいくつかの路線は時刻表がオープンデータにないため、駅は検索や徒歩の目的地にはできますが、乗車はできません。
- 暑さ指数は、4つの観測地点のうち最も近い地点の環境省の推定値で、日差しの影響を含みます。日陰では輻射熱が下がり、それがこのアプリの目的ですが、どれだけ下がるかの数字は示していません。

## フォルダ構成

```
geo/                 Python：PLATEAU、OpenStreetMap、ほこナビ、シェルター → data/build/geo
pipeline/            TypeScript：ODPT の電車とバス → network.json、夏の日の再現、ツール
src/server/shade/    太陽の位置、日陰エンジン、日陰の地図タイル
src/server/walk/     歩行グラフ、日差しのモデル、暑さをふまえた探索、道案内の文
src/server/          交通、駅の出入口とバス停、経路探索、暑さ、地名検索、API
src/web/             アプリ（React、MapLibre）
tests/               単体テスト（太陽、日陰、徒歩、RAPTOR、パイプライン）
docs/                スクリーンショットと検証結果
```
